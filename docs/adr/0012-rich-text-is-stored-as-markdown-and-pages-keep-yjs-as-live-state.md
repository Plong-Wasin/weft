# Rich text is written as Markdown; descriptions and Comments store it, Pages keep Yjs as the live state

Agents read and write rich text constantly, and the editor document (Tiptap JSON) cannot be read, diffed, or written by an Agent without a converter that today loses data without a warning: hard breaks, nested lists, headings below level 4, colors and highlights, and mentions, images and callouts that come back as placeholders. So the **written form** of every rich-text field becomes Markdown: GitHub Markdown plus Obsidian marks (`[[ABC-12]]`, `![[asset]]`, `> [!note]`, `==highlight==`) and a small allowlist of HTML (`<span style="color:...">` with a hex or basic color name, `<u>`, `<sub>`, `<sup>`). Anything outside the allowlist stays plain text, so Markdown from an Agent or an import cannot inject markup. Mentions, links and images carry a stable id, not only a display name, so renames do not break them.

A description and a Comment store the written form as the original. They are not edited by several people at once (last write wins), so nothing blocks this. Search text, mentions and Backlinks are derived from it on every save and can always be rebuilt. A Page and a Wiki page keep the Yjs document as the live editing state and keep ADR 0005 in force: comment anchors on a Wiki page are Yjs relative positions, and rebuilding the Yjs document from text on every load would break them. For these pages the written form is derived on every save and Agents, the CLI, MCP and the API read and write it; a write is applied to the Yjs document as today.

The editor is limited to what the written form can express, so a round trip is lossless by construction and a test proves it on real documents. We rejected storing the editor document and converting on read (what exists, and it loses data), a free-form rich editor converted to Markdown on every save (one converter bug silently corrupts the original), and Markdown as the only original for Pages (breaks comment anchors and replaces ADR 0005 without a reason that outweighs it). The cost: text alignment and table-cell background are removed from the editor and lost from existing documents; a converter and its tests must be built and kept; and the Markdown that mentions or images use points at ids in Weft, so another tool such as Obsidian shows them as plain text until an export step decides how to write them.

## Amendment: the stored document is a derived cache

`work_items.description_doc` (and the comment and version `body` documents) is a cache derived from the Markdown. It is written in the same statement as the Markdown, and it equals the parse of the stored Markdown (a fuzz test asserts this). The Markdown wins: if they ever differ, the Markdown is the truth. Readers serve the cached document when it is present and parse the Markdown otherwise. Legacy documents (the old editor JSON) are served for backfilled rows that nobody has edited since, because the backfill never rewrites them; the first save replaces them with the derived cache.
