# Task search

`GET /api/v1/workspaces/{workspace_id}/search?q=...&page=1&limit=20` searches task numbers, titles, descriptions, active comment bodies, and JSON Attribute values with PostgreSQL `ILIKE` substring matching. Task number matches are exact. Queries must contain 1–100 Unicode characters and at most 8 whitespace-separated terms; pages start at 1 and limits range from 1 to 50. Invalid query lengths, term counts, page sizes, pages, and cursors return HTTP 422 with an `error.code` and human-readable `error.message`.

Search and count queries apply Workspace membership and Project visibility/grants in PostgreSQL before selecting result text. Restricted Projects therefore do not contribute results, counts, snippets, or palette suggestions. Each hit includes a short snippet from the matching comment, description, title, or Attribute value, with a matching comment preferred. Results include `next_cursor`, the last returned task number when more results exist; pass it as `cursor` to continue. `page` remains supported for offset pagination.

Search does not split Thai text into words: an exact Thai sequence and any contiguous substring of it match; a query for only a fragment between Thai words does not match unless that fragment is present contiguously. No Thai word segmentation is claimed. This behavior is covered by `comments_search_export` tests for Thai title substring, Attribute value, and comment search. The command palette calls this same endpoint while typing, so searching a comment opens its Task.
