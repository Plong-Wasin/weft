# Weft can be served from one origin behind a Caddy reverse proxy, as an opt-in compose override

Today the web app, the API and MinIO are three origins (`:8080`, `:3000`, `:9000`). That forces CORS, a build-time `VITE_API_URL`, and a public S3 endpoint on its own port, and it makes TLS a per-service chore. We add `compose.proxy.yaml`, used together with `compose.yaml`, that puts one Caddy site (`SITE_ADDRESS`) in front and routes by path: `/actions/*` and `/api/*` to the API, `/mcp*` and `/.well-known/oauth-protected-resource*` to the MCP service, the rest of `/.well-known/*` to the API, `/live/*` to the live server (ADR 0005) once it exists, `/<S3_BUCKET>/*` to MinIO, everything else to the web container. The operator sets one variable, `WEFT_PUBLIC_URL`; the override derives `BETTER_AUTH_URL`, `WEB_ORIGIN` and `S3_PUBLIC_ENDPOINT` from it, and the web image is built with an empty `VITE_API_URL` so it calls the API with relative URLs. The plain `docker compose up` shape (several localhost ports) stays the default.

We chose Caddy over nginx for automatic HTTPS and a short config, and because Plane uses it. We rejected a subdomain for assets (`assets.<domain>`: not a single domain, and a second certificate) and path-prefix hosting such as `example.com/weft/` (it would change the SPA router, cookie paths, the Vite `base` and the service worker scope). Only a root domain is supported.

The cost: top-level paths become reserved, so workspace slugs `api`, `actions`, `mcp`, `live` and the bucket name are rejected on creation. The service worker gets a navigation denylist for the same prefixes, so a browser navigation to `/api/auth/oauth2/authorize` reaches the server and not the cached SPA shell. Presigned S3 signatures cover the Host header, so the proxy must forward the original Host to MinIO. `/api/events` (SSE) must not be buffered or compressed.
