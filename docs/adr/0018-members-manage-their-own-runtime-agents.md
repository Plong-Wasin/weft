# Members manage Agents they create on their own Runtime

This ADR supersedes ADR 0017's restriction that only a workspace Admin may configure or grant Projects to a Member-created Agent.

A non-Guest Member may create an Agent only on a Runtime they own and have shared with the workspace. The creator may manage that Agent's name, instructions, model, CLI model, concurrency, per-Run limits, monthly budget, enabled state, Project access and Agent access. They may not convert it to a server Agent or bind it to another person's Runtime. Guests cannot create or manage Agents. Workspace Admins retain full oversight and may configure any Agent; only Admins change the Agent's extra Action grants, Skill attachments, Triggers and Can wake Agents setting. An Admin may explicitly move a Member-owned Agent to another Runtime or to the Weft server; that transfer changes it to Admin-managed governance and the former creator loses configuration access.

The Agent starts with no Project access. Its creator can select only specific Projects in the same workspace where they currently have write access; `allProjects` is always refused for a Member. A selected Project remains usable only while the creator retains write access there. Run creation checks the Originator's current rights and the Agent creator's current rights; Runtime dispatch and every Runtime Run Action recheck creator access so revocation also stops queued work from starting or calling Weft Actions. A Member who is suspended, removed, changed to Guest, or no longer owns the Runtime loses the management capability. An ownership mismatch or missing workspace membership fails closed; an Admin can still manage or disable the Agent.

The Runtime owner retains the existing control of that Runtime's Agent access, sandbox profile and environment. Runtime Agents still use Autopilot, workspace Autopilot still gates whether Runs start, and the Agent's Action grants and Agent access remain separate: Project access alone does not let the Originator use the Agent. Member changes are audited under the same Agent activity records as Admin changes. Existing limits and deletion safeguards continue to apply.
